# چک‌لیست امنیتی آوال سیم

این چک‌لیست را **قبل از انتشار عمومی** و سپس در هر بازبینی دوره‌ای کامل کنید. هر مورد را با «انجام شد» یا «دلیل پذیرش ریسک» علامت بزنید.

---

## ۱. رمزها و پیکربندی

- [ ] `APP_ENV=production` است.
- [ ] `APP_DEBUG=false` است (هیچ Stack Trace به کاربر نمایش داده نمی‌شود).
- [ ] `APP_KEY` تصادفی، حداقل ۳۲ بایت و مخصوص همین نصب است.
- [ ] `config/env.php` خارج از وب‌ریشه و با مجوز `600` است.
- [ ] رمز دیتابیس قوی و متفاوت از رمزهای دیگر است.
- [ ] `MIGRATION_TOKEN` پس از نصب از env حذف یا باطل شده و `run_migration.php` پاک شده است.
- [ ] `CRON_TOKEN` تصادفی و متفاوت از `APP_KEY` است.
- [ ] کلیدهای درگاه و پیامک فقط در env هستند و در گیت/لاگ/پنل عمومی نیستند.
- [ ] فایل `config/env.php` در `.gitignore` قرار دارد.
- [ ] رمز پیش‌فرض `admin` تغییر کرده یا حساب با رمز تصادفی migration جایگزین شده است.
- [ ] حساب‌های آزمایشی/نماینده تستی حذف یا غیرفعال شده‌اند.

## ۲. احراز هویت و دسترسی

- [ ] 2FA برای همه ادمین‌ها فعال است.
- [ ] رمز ادمین حداقل ۱۲ کاراکتر و غیرقابل حدس است.
- [ ] RBAC بررسی شده: نماینده به `/admin` و مشتری به `/reseller` دسترسی ندارد.
- [ ] Rate Limit ورود فعال است (۵ تلاش / ۱۰ دقیقه) و در تست، قفل شدن حساب دیده شده.
- [ ] `login_attempts` و `audit_logs` قابل مشاهده و بررسی هستند.
- [ ] Session پس از ورود/خروج بازتولید/پاک می‌شود.
- [ ] `SESSION_SECURE=true` و سایت فقط HTTPS سرو می‌شود.
- [ ] کوکی‌ها `HttpOnly` و `SameSite=Lax` هستند.
- [ ] مسیر `/admin` و `/reseller` در robots/noindex هستند.
- [ ] دسترسی مستقیم به سفارش مهمان فقط با session معتبر یا لینک رهگیری کار می‌کند.

## ۳. وب‌سرور و فایل‌ها

- [ ] DocumentRoot فقط `public_html` است.
- [ ] `app/`, `config/`, `storage/`, `database/`, `views/`, `tests/` داخل وب‌ریشه نیستند.
- [ ] `public_html/.htaccess` فعال و `AllowOverride` برای آن مجاز است.
- [ ] `Options -Indexes` برقرار است و لیست پوشه‌ها نمایش داده نمی‌شود.
- [ ] `public_html/assets/uploads/.htaccess` اجرای PHP را در پوشه آپلود مسدود می‌کند.
- [ ] فایل‌های `.env`, `.sql`, `.log`, `.md`, `.bak`, `.git` از وب مسدود شده‌اند.
- [ ] `dev_router.php` روی هاست production وجود ندارد.
- [ ] `run_migration.php` حذف شده است.
- [ ] `storage/` و `config/env.php` با مجوز درست (`775` / `600`) هستند.
- [ ] آپلودها با ImageService اعتبارسنجی MIME/پسوند/اندازه می‌شوند.
- [ ] فایل‌های حساس بکاپ (`storage/backups`) از وب قابل دانلود نیستند.

## ۴. ورودی، خروجی و تزریق

- [ ] همه Queryها با Prepared Statement/پارامتر اجرا می‌شوند.
- [ ] فیلترهای جستجو (قیمت، تاریخ تولد، الگو، پیش‌شماره) ورودی را پاک‌سازی می‌کنند.
- [ ] خروجی HTML با `e()` escape می‌شود.
- [ ] محتوای صفحات ثابت فقط توسط ادمین قابل ویرایش است (HTML اعتمادشده) و برای نقش‌های دیگر قابل نوشتن نیست.
- [ ] CSRF روی همه POSTها فعال است؛ درخواست بدون توکن با 419 رد می‌شود.
- [ ] درگاه پرداخت فقط با Callback معتبر و تأیید سمت سرور نهایی می‌شود.
- [ ] Callback تکراری/رفرش باعث پرداخت دوباره نمی‌شود (Idempotency تست شده).
- [ ] مبلغ نهایی از دیتابیس محاسبه می‌شود، نه از فرم/کلاینت.
- [ ] شماره سیم‌کارت با تراکنش/رزرو اتمیک به فروش می‌رسد و دو خرید هم‌زمان یک شماره نمی‌گیرند.
- [ ] خطاهای Validation به کاربر پیام فارسی و امن می‌دهند (بدون SQL/Stack Trace).
- [ ] هدرهای امنیتی (CSP, X-Frame-Options, nosniff, Referrer-Policy) ارسال می‌شوند.
- [ ] CSP فقط CDNهای لازم (Tailwind/Alpine/فونت) را مجاز می‌کند.

## ۵. پرداخت

- [ ] درگاه واقعی (نه fake) فعال است.
- [ ] `FAKE_GATEWAY_ENABLED=false` است.
- [ ] Merchant/API Key در env است و در کد/فرانت نیست.
- [ ] آدرس Callback در پنل درگاه با `APP_URL` هم‌خوان است (HTTPS).
- [ ] مبلغ ارسالی ریال است (تومان × ۱۰) و با مبلغ سفارش مطابقت دارد.
- [ ] پرداخت ناموفق، سفارش را قفل نمی‌کند و رزرو آزاد می‌شود.
- [ ] `reconcile_payments` هر ۱۰ دقیقه اجرا می‌شود.
- [ ] تراکنش‌های معلق پس از ۲ ساعت ناموفق/آزاد می‌شوند.
- [ ] لاگ پرداخت‌ها (`payments`) شامل Authority/Reference و وضعیت است.
- [ ] بازگشت وجه فقط توسط ادمین و با ثبت Audit انجام می‌شود.

## ۶. رزرو و موجودی

- [ ] رزرو ۱۵ دقیقه‌ای است و Cron آزادسازی هر ۵ دقیقه اجرا می‌شود.
- [ ] رزرو منقضی، شماره را به وضعیت available برمی‌گرداند.
- [ ] وضعیت `sold` فقط پس از پرداخت موفق ثبت می‌شود.
- [ ] شماره فروخته‌شده قابل حذف نیست (سابقه سفارش حفظ می‌شود).
- [ ] موجودی مودم پس از خرید کاهش می‌یابد و در صورت صفر شدن از فروشگاه مخفی می‌شود.
- [ ] Jobها با `claimNext` و `FOR UPDATE SKIP LOCKED` پردازش می‌شوند (بدون ارسال دوباره).

## ۷. پیامک و ایمیل

- [ ] اعتبار پنل پیامک مانیتور می‌شود.
- [ ] متن پیامک‌ها حاوی اطلاعات حساس (رمز/کد کامل) نیست.
- [ ] ارسال پیامک فقط از صف/Cron انجام می‌شود، نه در Request.
- [ ] Retry ناموفق‌ها محدود است (حداکثر ۵ تلاش).
- [ ] فرم تماس Rate Limit دارد (۳ پیام / ۱۵ دقیقه).
- [ ] ایمیل اعلان ادمین فقط به آدرس خودتان می‌رود.
- [ ] هدرهای SPF/DKIM/DMARC دامنه تنظیم شده‌اند (اگر ایمیل ارسال می‌شود).

## ۸. لاگ، مانیتورینگ و بکاپ

- [ ] `storage/logs` نوشته می‌شود و دسترسی عمومی ندارد.
- [ ] Audit Log برای ورود، تغییر قیمت، تغییر وضعیت سفارش، حذف و تنظیمات فعال است.
- [ ] لاگ‌ها اطلاعات حساس (رمز، توکن، کلید درگاه) ثبت نمی‌کنند.
- [ ] بکاپ روزانه خودکار اجرا می‌شود و فقط ۵ نسخه نگه داشته می‌شود.
- [ ] بکاپ‌ها خارج از هاست (Offsite) کپی می‌شوند.
- [ ] بازیابی بکاپ یک‌بار روی محیط تست انجام شده است.
- [ ] Cronها با لاگ و هشدار شکست پایش می‌شوند.
- [ ]فضای دیسک و مصرف دیتابیس پایش می‌شود.
- [ ] برای خطاهای 500 آلارم/بررسی روزانه وجود دارد.

## ۹. حریم خصوصی و قوانین

- [ ] متن «قوانین و مقررات» و «حریم خصوصی» با کسب‌وکار واقعی هم‌خوان است.
- [ ] شماره تماس و آدرس پشتیبانی واقعی است.
- [ ] داده‌های مشتری فقط برای تحویل سفارش استفاده می‌شود.
- [ ] درخواست حذف داده طبق رویه پشتیبانی قابل انجام است.
- [ ] دسترسی به دیتابیس فقط برای افراد لازم است.
- [ ] اطلاعات پرداخت (شماره کارت/CVV) هرگز ذخیره نمی‌شود.

## ۱۰. به‌روزرسانی و واکنش به حادثه

- [ ] نسخه PHP و MariaDB پشتیبانی می‌شود و به‌روزرسانی امنیتی می‌گیرد.
- [ ] دسترسی FTP/پنل هاست با 2FA و رمز قوی محافظت می‌شود.
- [ ] حداقل سالی یک‌بار رمزها و کلیدها چرخش (Rotate) می‌شوند.
- [ ] در صورت افشای کلید، کلید فوراً باطل و جایگزین می‌شود.
- [ ] رویه پاسخ به حادثه: قطع دسترسی، بررسی Audit، بازگردانی بکاپ سالم، اطلاع‌رسانی.
- [ ] فایل‌های ناشناخته در `public_html` و `assets/uploads` پایش می‌شوند.
- [ ] `open_basedir` و `disable_functions` هاست بررسی شده‌اند.

## تست‌های امنیتی که باید انجام شود

1. POST بدون CSRF → باید 419 بدهد.
2. ورود با نقش نماینده به `/admin` → باید رد/ریدایرکت شود.
3. مشاهده سفارش با کد رهگیری در session جدید → باید 404 بدهد.
4. آپلود فایل PHP با پسوند `.jpg` → باید رد شود.
5. درخواست به `/cron/run.php` بدون توکن → باید 403 بدهد.
6. Callback تکراری درگاه → نباید پرداخت/سفارش دوباره ثبت شود.
7. تغییر قیمت در فرم سبد/Checkout → نباید مبلغ نهایی را تغییر دهد.
8. جستجوی `' OR 1=1 --` → نباید خطای SQL یا داده اضافی بدهد.
9. XSS در نام مشتری/پیام تماس → باید escape شود.
10. ۶ تلاش ورود ناموفق → باید موقتاً Rate Limit شود.

## در صورت بروز مشکل

- لاگ برنامه: `storage/logs/app-*.log`
- لاگ Cron: `storage/logs/cron.log`
- لاگ وب‌سرور: DirectAdmin → Error Logs
- بررسی دیتابیس: phpMyAdmin
- بازگردانی: بکاپ روز قبل + بررسی Audit Log

> این چک‌لیست جایگزین مشاوره امنیتی تخصصی یا تست نفوذ نیست. برای فروشگاه با تراکنش واقعی، یک بازبینی امنیتی مستقل توصیه می‌شود.
